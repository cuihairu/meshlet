## Step 2：§2.5 51820 撞绑——v2 事故副产品（形态比预设更广）

v2 尝试（任务 MeshletWgNtStep1，11:18:25 SYSTEM）因假 conf 文件名为
`wg-meshlet-probe.conf`，装成了**不同名第二隧道** wg-meshlet-probe
（listen_port=51820，抄自生产 conf）——非但没做成同名互踩，反而实占
UDP 51820：原 wg-meshlet 服务重装后 bind 失败 STOPPED，形成 §2.5 的
活体复现，且证明**不同名第二实例也撞**（端口是机器级资源，比分析文档

## Step 3：wireguard-nt 双 adapter PoC（真机提权，8/8 PASS）

### 关键 staging 事实

官方 WireGuard for Windows 安装目录**不含 wireguard.dll**（只有
wg.exe/wireguard.exe——tunnel 服务静态链在 exe 内）：
```
2026/09/20  14:15           140,408 wg.exe
2026/09/20  14:15           9,354,360 wireguard.exe
```
故 PoC 从官方 release 分发 wireguard-nt 1.1 amd64 dll（
download.wireguard.com/wireguard-nt/wireguard-nt-1.1.zip，
SHA256 b1b85e072c45d81358be29d94c599dc76652f912be8c0f0a41e2d5d89a6461d3）
staging 至 `C:\Users\cui\wgnt\wireguard.dll`——**切换方案的 dll 必须随
meshlet 分发，不能依赖用户已装的 WireGuard**。

PoC exe：scratch 分支 wg-nt-poc（源码 scratch/userspace-wg-poc 一脉，
exe SHA256 前 16 位 8d89cb47bd2f3bb6）。执行方式：schtasks SYSTEM 分离
（任务 MeshletWgNtPoc，同 MeshletOcUp 先例）。首跑失败两次：
①schtasks 内嵌引号 /TR 折损→driver .ps1 铁律；②Start-Process
-ArgumentList 数组形不给含空格参数加引号（`C:\Program Files\...` 在

1. **①服务单例消失**：`sc query WireGuardTunnel$wg-mlt-a` → 1060——

2. **②netstat 两端口共存**：51821/51822 同时可见，51820 冲突形态消失

## 过程坑备忘（真机实测，后续接线直接受益）

1. **SSH 会话 installtunnelservice 静默拒**：exit=0 但 conf 未生效
   （GUI 消息框弹不出、stderr 无输出）——真机操作必须 schtasks SYSTEM
   分离执行；`/managerservice` 被杀后 install 自动重生。
2. **对已存在同名服务 installtunnelservice 静默拒**（exit=0）——必须
   先 uninstall 再 install（agent install_plan 已是这个语义，实证正确）。
3. **schtasks 内嵌引号 /TR 一律折损**——带引号参数必须走 driver .ps1
   文件（PowerShell 单引号包 /TR 值）。openclaw pwsh 会把服务名
   `$wg` 插值吃掉（1060 假象）——`sc query state= all` 或 .ps1 文件绕开；
   imac shell 行为不同（cmd-like，`$` 存活）。
4. **Start-Process -ArgumentList 数组形不给含空格参数加引号**——路径
   劈裂；用单字符串引号形。
5. `wg show dump` 首行含私钥——取证一律 `-Skip 1`。
6. 僵尸隧道进程判定必须结合服务 STATE（运行进程命令行=僵尸形态相同）。
