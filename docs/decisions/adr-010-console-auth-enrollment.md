# ADR-010：控制台认证和设备注册安全模型

- 状态：Accepted
- 日期：2026-10-14
- 期次：Phase 0
- 来源：[存档 §11 / §16](../review/chatgpt-2026-10-13.md#_11-身份、认证与授权)

## 背景

两类身份必须分离（§11.1）：控制台用户（管理人）与设备（Overlay 成员）。设备不能因持有 WireGuard 密钥获得管理权限。

## 问题

控制台如何认证？设备如何安全加入？

## 候选方案

1. **本地管理员 + Argon2id + Cookie 会话 + CSRF 防护；设备经一次性邀请加入**
2. OAuth/SSO 外接（§5.2 第一版不需要）
3. 共享 Token / 无认证（§11.4 禁止）

## 决定

- 控制台：第一版本地管理员账号；密码 Argon2id 哈希；登录限流；Cookie 会话带 `Secure`/`HttpOnly`/`SameSite` + CSRF 双提交；生产强制 HTTPS（或受信反代终止 TLS）；无硬编码默认密码（首启引导设置）；管理 API 全部认证、敏感操作授权 + 审计事件；
- 设备加入：管理员生成一次性邀请（目标 Network + 有效期 + 次数上限；Token 用安全随机生成，**库里只存摘要**，支持过期/撤销，不入日志）；客户端本地生成 WireGuard 密钥对，**私钥不出客户端**，服务端只登记公钥、分配虚拟 IP（ADR-004）、更新 Peer；
- 撤销：标记 → 密钥失效 → 移除 Peer → 移除路由/Alias 关系 → 应用新版本（ADR-009）→ 记录结果；不确定生效即报失败。

## 理由

- 本地账号满足单管理员的 v1 场景，复杂身份系统明确推迟（§5.2）；
- 邀请摘要存储 + 一次性语义使 Token 泄漏窗口最小。

## 缺点与风险

- 单管理员无角色分层——数据模型从开始区分 Network 归属（§12.1），为多用户留路；
- Cookie/CSRF 实现细节易错，纳入安全测试清单（§18.4）。

## 重新评估条件

- 多用户/多角色管理需求；
- 需要 OAuth/LDAP 等外部身份源；
- 邀请流程实测存在重放竞态无法在应用层闭合。
