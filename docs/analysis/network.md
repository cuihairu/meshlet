# 网络设计：Overlay、中继、LAN 路由与 Alias

> 来源：[ChatGPT 存档 §6–§9](/review/chatgpt-2026-10-13#_6-ip-地址规划)。外部意见，全部【待核】。本主题是外部意见标注的高风险区。

## Overlay IPv4 与 IPAM（§6）

【待核】（[存档 §6.1](/review/chatgpt-2026-10-13#_6-1-overlay-ipv4)）：

- 第一版仅 IPv4；默认 CIDR `10.240.0.0/16` 是**默认值建议，不是协议常量**；
- 创建网络时可选 Overlay CIDR，做格式/网络地址/广播地址/保留地址检查；
- 分配避免重复；VPS 的 Overlay 地址不分配给普通客户端；
- 初始约定 `VPS=10.240.0.1`、`Clients=10.240.0.2+`，但按 Network CIDR 计算，不硬编码。

【待核】CIDR 冲突检测至少覆盖（[存档 §6.2](/review/chatgpt-2026-10-13#_6-2-cidr-冲突检测)）：Overlay↔Alias 重叠、Overlay 与本机/VPS 已有路由冲突、Alias↔Alias、同网络 LAN Route 冲突、Alias Target 与所绑 LAN Route 不一致、客户端本地路由冲突（由 Agent 二次检查上报）。

【待核】冲突分三类处理（[存档 §6.3](/review/chatgpt-2026-10-13#_6-3-不要假设所有私网地址都可以直接使用)）：服务端已知 / 客户端本地发现 / 无法确认。无法确认时**显示警告而不是宣称可用**（客户端可能已占用 `10.240.0.0/16` 等网段）。

## WireGuard 中心中继（§7）

【待核】拓扑：所有客户端只建到 VPS 的隧道，客户端间通信由 VPS 内核转发（[存档 §7.1](/review/chatgpt-2026-10-13#_7-1-第一版拓扑)）。

【待核】Peer 原则（[存档 §7.2](/review/chatgpt-2026-10-13#_7-2-peer-配置原则)）：

- VPS 为每设备独立 Peer，能按目标 Overlay IP 找到对应 Peer；
- 客户端 `AllowedIPs` 必须与目标路由一致，**不能把所有流量都指向隧道**；
- 第一版默认只路由：Overlay 网段 + 明确发布的远端 LAN + Alias 网段。

【待核】VPS 转发要求（[存档 §7.3](/review/chatgpt-2026-10-13#_7-3-vps-转发要求)）：IPv4 forwarding、Peer AllowedIPs、Overlay 路由、FORWARD 防火墙、网络间隔离、连接跟踪与 NAT。必须用真实集成测试证明四件事：

1. A 能访问 B 的 Overlay IP；
2. B 能返回 A 的响应；
3. 未授权设备不能访问受保护网络；
4. 设备撤销后旧配置不能继续建立有效连接。

【待核】SNAT 纪律（[存档 §7.4](/review/chatgpt-2026-10-13#_7-4-中继流量与-snat)）：Overlay 设备间通信保持原始源地址；**不为图省事把整个 Overlay 的流量无差别 SNAT 到 VPS 地址**；访问真实 LAN 时单独处理返回路由。

【待核】MTU（[存档 §7.5](/review/chatgpt-2026-10-13#_7-5-mtu)）：封装有开销，MTU 策略可配置 + 基本诊断；第一版不要求自动探测最优 MTU，但要避免明显不合理配置并能解释分片问题。

【待核】可用性边界（[存档 §7.6](/review/chatgpt-2026-10-13#_7-6-中继能力边界)）：依赖 VPS 转发——VPS 需放行 UDP、有带宽；VPS 中断则跨设备连接与控制台均中断。这是第一版明确接受的限制。

## 异地 LAN 路由（§8）

【待核】发布路由：网关设备发布 CIDR，其他客户端把该网段指向隧道；网关启用 IPv4 转发（[存档 §8.1](/review/chatgpt-2026-10-13#_8-1-发布路由)）。

【待核】**返回路由是最易出问题的部分**（[存档 §8.2](/review/chatgpt-2026-10-13#_8-2-返回路由)），两种模式：

| 模式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A · 真实双向路由 | 在 LAN 路由器配置 Overlay CIDR → 网关的静态路由 | 保留真实源 IP；日志/ACL 清晰 | 要求用户能管理 LAN 路由器 |
| B · 受控 SNAT | 网关把来自 Overlay 的流量 SNAT 成自身 LAN 地址 | 适合普通家庭网络；LAN 主机无需知道 Overlay | LAN 看到的来源是网关；基于源 IP 的策略受影响 |

第一版在 LAN Route 配置中**明确显示所采用的返回路径模式**；不能只配出站忽略返回路由。

【待核】路由冲突（[存档 §8.3](/review/chatgpt-2026-10-13#_8-3-路由冲突)）：客户端本地与远端 LAN 同网段时，**不能静默安装普通路由指望自动解决**，应提示用户为远端 LAN 配 Alias。

## Alias 地址映射（§9）

【待核】语义（[存档 §9.1](/review/chatgpt-2026-10-13#_9-1-产品语义)）：为真实 LAN 提供独立虚拟前缀，客户端只访问 Alias 地址，由对应网关转换。

【待核】映射规则（[存档 §9.2](/review/chatgpt-2026-10-13#_9-2-映射规则)）：

- 第一版要求 **Alias 与 Target 前缀等长**，一对一前缀替换（`10.241.1.10 → 192.168.1.10`）；
- 不支持非等长映射、任意端口代理、DNS 动态映射；
- 转换前六项检查：Alias 在已分配前缀内、Target 在目标 LAN 前缀内、无冲突、目标 LAN 由有效网关发布、发起设备有权访问、转换规则已成功应用。

【待核】实现位置（[存档 §9.4](/review/chatgpt-2026-10-13#_9-4-推荐的第一版实现方式)）：**Alias 转换在目标 LAN 网关上实施**（DNAT/SNAT 在网关执行），VPS 只需知道 Alias 前缀对应哪个网关 Peer。理由：网关知道真实出口、可直接访问目标主机、避免 VPS 上建所有远端 LAN 的重叠路由。

【待核】DNAT 与 SNAT（[存档 §9.5](/review/chatgpt-2026-10-13#_9-5-dnat-与-snat)）：仅 DNAT 通常不够——LAN 主机返回路由不指向网关时响应会走默认路由。第一版默认兼容模式允许对 Alias 流量受控 SNAT，并在控制台明示「LAN 看到的源是网关」；用户配好返回路由后可启用保留源地址模式。

【待核】协议边界（[存档 §9.6](/review/chatgpt-2026-10-13#_9-6-alias-协议兼容边界)）：目标是常见 TCP/UDP/ICMP IPv4；源 IP 依赖的 ACL 受 SNAT 影响；广播/组播/二层发现不保证跨网段；协议负载内嵌 IP 的应用可能失效；**Alias 不是二层桥接，不是应用层代理，不得宣称对所有协议透明**。

流量路径（[存档 §9.3 时序图](/review/chatgpt-2026-10-13#_9-3-alias-流量路径)）：客户端 → VPS Hub → 网关 DNAT（+SNAT）→ LAN 主机 → 连接跟踪反向 NAT → 原路返回。
